# ADR-0002: 바이낸스 선물/레버리지로 전환

**Status:** Accepted
**Date:** 2026-09-28
**Deciders:** account owner (동동), Claude Code session

## Context

ADR-0001은 업비트 KRW 현물, 레버리지 없음으로 시작했다. 동동님이 처음부터 선물·
레버리지를 쓸 계획이라고 확인했다(2026-09-28). 국내 거래소(업비트·빗썸 등)는 한국
규제상 코인 선물·레버리지 상품을 취급하지 않으므로, 선물을 쓰려면 해외 거래소가
필요하다.

## Decision

1. **매매 거래소를 바이낸스 선물로 바꾼다.** 이유: 유동성·API 안정성이 가장 좋고,
   과거 체결/펀딩비 데이터를 공개적으로 받을 수 있어 검증이 가능하다.
2. **원화 보관과 국내 신고는 계속 업비트에서 한다.** 실거래 자금은 업비트에서 KRW로
   보유하다가, ADR-0003의 사람 승인 자금이동 절차를 통해 USDT로 바꿔 바이낸스로
   옮긴다. 이 프로젝트가 국내 규제를 우회하도록 설계하지 않는다 — 자금 이동은
   합법적인 개인 자산 이동(자기 명의 계좌 간)이며, 각 이동은 사람이 직접 실행한다.
3. **레버리지·청산·펀딩 설계는 이 ADR에서 완료하지 않는다.** 다음이 필요하며,
   각각 코드와 테스트가 준비되기 전에는 실거래를 켜지 않는다(`live/safety_gate.py`가
   막는다):
   - `risk/sizing.py`에 레버리지 파라미터, 증거금 한도, 청산가 계산 추가.
   - `backtest/costs.py`에 펀딩비(8시간마다) 반영.
   - `live/kill_switch.py`에 청산 근접(마진비율) 트리거 추가.
   - 백테스트가 청산을 시뮬레이션해서, 실제였으면 청산됐을 드로다운을 생존한 것처럼
     보고하지 않게 한다(`backtest-integrity-review` 스킬의 "선물 전용" 항목).
4. **규제 확인은 사용자 책임.** 해외 파생상품 거래소 이용 관련 현재 규정은 이 세션이
   확정적으로 알 수 없다. 실제 자금을 옮기기 전에 동동님이 직접 최신 규정을 확인한다.

## Consequences

- `docs/decisions/ADR-0001-swing-first-bootstrap.md`의 "선물 제외" 결정은 이 ADR로
  대체된다(ADR-0001 자체는 그대로 두고, 이 ADR이 갱신한다고 기록).
- 스윙 검증 순서(워크포워드 → PBO/DSR → TEST 잠금)는 레버리지가 있어도 그대로
  적용한다 — 다만 백테스트에 펀딩비·청산이 빠지면 결과가 낙관적이다.
- 레버리지 사이징·청산 시뮬레이션·펀딩비 백테스트는 후속 PR에서 구현한다(이번 PR은
  거래소 전환 결정과 자금이동/세금 기능만 포함).
