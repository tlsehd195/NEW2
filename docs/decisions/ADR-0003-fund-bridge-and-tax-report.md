# ADR-0003: 자금이동(업비트→바이낸스)과 세금 리포트: 사람 승인 게이트

**Status:** Accepted
**Date:** 2026-09-28
**Deciders:** account owner (동동), Claude Code session

## Context

ADR-0002에서 매매 거래소를 바이낸스 선물로 정하면서, 원화는 계속 업비트에 보관하다가
필요할 때 USDT로 바꿔 바이낸스로 옮기는 흐름이 생겼다. 동동님이 "버튼 누르면 자동으로
사고 옮겨지는" 기능과 세금 계산 기능을 요청했다(2026-09-28).

자금 이동은 실제 돈이 국경을 넘어 움직이는, 되돌리기 어려운 동작이다. 이 프로젝트의
킬 스위치·라이브 승인과 같은 원칙(자동 시스템은 스스로 시작할 수 없고, 사람이 매번
명시적으로 확인해야 한다)을 그대로 적용한다.

## Decision

1. **자금 이동은 절대 자동/예약 실행되지 않는다.** 견적(`quote_transfer`)까지는 자동으로
   낼 수 있지만, 실제 구매+출금(`execute_transfer`)은 매번 사람이 터미널에서 직접
   `scripts/run_fund_transfer.py`를 실행하고 확인 문구를 입력해야 한다. 이 경로를 호출
   하는 코드는 `src/`나 다른 자동 스크립트에 추가하지 않는다(AST 테스트로 검사).
2. **승인은 재사용할 수 없다.** `FundTransferApproval`은 특정 `quote_id`에 묶여 있어서,
   한 번 낸 견적이 아닌 다른 견적이나 다음 이체에 재사용할 수 없다. 견적에는 유효시간
   (기본 5분)이 있고, 만료되면 거절한다.
3. **한도는 설정하지 않으면 거래를 막는다(fail-closed).** `BridgeConfig.max_krw_per_transfer`
   가 없으면 `execute_transfer`가 예외를 낸다.
4. **실제 거래소 연동은 이번 PR에 포함하지 않는다.** `DomesticExchangeClient`/
   `WithdrawalClient`는 Protocol이고, `scripts/run_fund_transfer.py`는 기본적으로
   아무 자금도 움직이지 않는 더미 클라이언트로 동작한다. 실제 API 키를 연결하는 건
   동동님이 직접 하거나, 그렇게 해달라고 명시적으로 요청했을 때 별도 작업으로 한다.
5. **트래블룰 확인은 사용자 책임.** 업비트는 자체적으로 검증된 주소/거래소로만 출금을
   허용하며, 바이낸스가 여기 포함되는지는 계정별 상황에 달려 있어 이 세션이 확인할 수
   없다. 실제 이체 전에 업비트 고객센터·공지로 직접 확인한다.
6. **세금 리포트는 조언이 아니라 장부 계산이다.** `tax/realized_gains.py`는 FIFO로
   실현손익을 계산할 뿐, 세율이나 신고 의무를 판단하지 않는다. 한국의 가상자산
   양도소득 과세 시행 여부·시기는 이 세션이 확정적으로 알 수 없으므로, 실제 신고
   전에는 세무사나 최신 세법을 직접 확인해야 한다는 경고를 리포트에 남긴다.
7. **세금 계산은 KRW 기준 체결(Fill)만 받는다.** 바이낸스 USDT 마진 거래를 KRW로
   환산하는 것은 이 모듈의 책임이 아니다 — 호출하는 쪽이 각 체결 시점의 환율로 미리
   환산해서 넘긴다. 잘못된 환산을 이 모듈이 대신 판단하지 않는다.

## Consequences

- `funding/bridge.py`와 `funding/approval.py`는 `.claude/hooks/protect-safety-files.sh`로
  보호되며, `tests/test_safety_boundaries.py`의 AST 검사 대상에 추가된다.
- 실거래 자금 이동을 실제로 쓰려면 별도로: (a) 업비트에서 출금 주소/거래소 화이트리스트
  확인, (b) 실제 `DomesticExchangeClient`/`WithdrawalClient` 구현과 API 키 연결이
  필요하다. 둘 다 이 PR 범위 밖이다.
- 세금 리포트는 거래 기록(`journal/trade_journal.py`)이나 별도로 넘긴 `Fill` 목록에서
  계산한다. 선물 손익(펀딩비, 청산 포함)의 실현손익 처리는 ADR-0002의 레버리지 설계가
  끝난 뒤 이 모듈을 확장한다.
