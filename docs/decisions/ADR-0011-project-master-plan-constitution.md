# ADR-0011: PROJECT_MASTER_PLAN.md 도입: 세션 간 연속성을 위한 헌법·읽기순서 체계

**Status:** Accepted
**Date:** 2026-09-28
**Deciders:** account owner, Claude Code session

## Context

동동님이 프로젝트 착수 당시 전달한 브리핑 문서(NEW- 프로젝트 경험을 바탕으로 작성,
`coin-trading-bootstrap-instructions.md`)는 `PROJECT_MASTER_PLAN.md` + "헌법(Constitution)"
패턴을 강력 추천했다: "이 프로젝트는 AI가 기억하는 프로젝트가 아니라 파일이 기억하는
프로젝트다" -- 새 세션은 대화 맥락 없이 시작하므로, 반복되지 않아야 할 규칙(자금 이동은
사람만, fail-closed, 검증 순서 생략 금지 등)을 대화 요약이 아니라 파일에 고정해야 한다.

이 프로젝트는 이미 여러 세션(코디네이터/스레드 세션, 압축 이후 재개된 세션 등)이
이어서 작업하는 구조이고, 이번 세션도 컨텍스트 압축으로 이전 대화를 요약본으로만
이어받았다 -- 브리핑 문서가 경고한 바로 그 상황이다. CLAUDE.md가 이미 핵심 안전
규칙(검증 순서, 자금 이동 사람 전용, fail-closed 등)을 담고 있지만, "새 세션이 정확히
어떤 순서로 무엇을 읽어야 하는지"와 "지금까지 뭘 시도했고 뭐가 살아있는 방향인지"를
한 곳에 정리한 문서는 없다 -- 지금은 이 정보가 `/tmp/claude/memory`(세션마다 접근
가능 여부가 다를 수 있음)와 대화 요약에 흩어져 있다.

## Decision

1. **`PROJECT_MASTER_PLAN.md`를 저장소 루트에 만든다.** 맨 위에 "새 세션은 반드시 이
   순서로 읽어라": ① 이 문서 전체 → ② `docs/PROJECT_STATUS.md`(현재 상태) → ③
   `docs/decisions/`(ADR 전체, 특히 최근 것) → ④ CLAUDE.md(코드 레벨 규칙) → ⑤ 작업
   중인 부분의 관련 파일.
2. **"헌법(Constitution)" 섹션을 두되, CLAUDE.md와 내용을 중복 나열하지 않고
   요약 + 링크로 연결한다.** CLAUDE.md가 이미 절대 규칙(검증 순서, 사람 전용 행위,
   안전 파일, fail-closed, provenance)을 담고 있으므로, `PROJECT_MASTER_PLAN.md`는
   그 규칙들을 "왜"와 "우선순위"까지 포함해 한 단계 위에서 설명하는 문서로 삼는다 --
   두 문서가 어긋나면 CLAUDE.md 쪽이 코드가 실제로 검사하는 규칙이므로 우선한다.
3. **`docs/PROJECT_STATUS.md`를 만들고, 가설 하나가 끝날 때마다(락 걸릴 때) 갱신한다.**
   현재 진행 상황(가설 H-0001~, 살아있는 방향, 죽은 방향, 다음 단계 후보)을 담아
   메모리나 대화 요약에 의존하지 않고도 새 세션이 3분 안에 "지금 뭘 하고 있었는지"를
   파악할 수 있게 한다.
4. **작은 변경(파라미터 값, 버그 수정)은 ADR 없이, 큰 변경(아키텍처·안전장치·헌법
   조항)은 ADR 작성 후 `PROJECT_MASTER_PLAN.md`/`PROJECT_STATUS.md` 갱신 순서로
   진행한다.** 이 ADR 자체가 그 예시다.

## Consequences

- 새 세션이 대화 요약 없이도(또는 압축된 요약만 가지고도) 빠르게 현재 상태를 파악할
  수 있다 -- 이번 세션이 겪은 압축 이후 재개 과정이 더 매끄러워진다.
- `docs/PROJECT_STATUS.md`를 매 가설마다 갱신하는 추가 작업이 생긴다 -- 게을리하면
  문서가 오히려 낡은 정보로 새 세션을 오도할 위험이 있으므로, 락 커밋에 상태 갱신을
  묶어서 잊지 않게 한다.
- CLAUDE.md는 코드가 실제로 강제하는 규칙(AST 테스트, 훅)의 원천으로 남고,
  `PROJECT_MASTER_PLAN.md`는 그 위의 맥락/우선순위 설명으로 역할을 나눈다 -- 둘이
  어긋나면 CLAUDE.md/코드가 진실이다.
