# ADR-0025: 지표 투표: 변동성 게이트와 펀딩비·미결제약정 지표

**Status:** Accepted
**Date:** 2026-10-02
**Deciders:** account owner (동동, "변동성 게이트와 펀딩비·OI 지표를 붙이자"에 "둘 다"로 승인), Claude Code session

## Context

ADR-0023 후보의 기본 패널 6개 중 추세·모멘텀 계열 4개는 서로 상관이 높다(합성 평균 |상관|
0.70). 동동님은 "겹치지 않고 서로 다른 역할"을 원했다. 캔들만으로는 새 역할을 만들 수 없어서
변동성(방향 없음)은 게이트로, 크립토 고유 정보인 펀딩비와 미결제약정(OI)은 투표로 추가한다.

## Decision

1. **변동성 게이트(투표 아님).** 단기(10봉)/장기(60봉) 로그수익률 표준편차 비율이
   `[0.5, 2.0]` 밖이면 *진입만* 막는다. 청산은 막지 않는다. 방향 정보가 없는 양을
   투표에 섞으면 방향 신호를 희석하기 때문이다. 문턱값은 결과를 보기 전에 고정했다.
2. **펀딩 쏠림 투표(`funding_crowding`).** 최근 9회 정산(3일) 평균 펀딩이 높으면 롱 쏠림이라
   약세(-), 낮으면 숏 쏠림이라 강세(+). 역추세 방향이다.
3. **OI 확인 투표(`oi_confirm`).** 5일 가격 변화는 같은 기간 OI가 *늘었을 때만* 반영한다
   (새 포지션이 따라붙은 움직임). OI가 줄거나 그대로면 기권(0). 반대 방향 투표는 하지 않는다.
4. 2~3번은 논문에서 나온 규칙이 아니라 설계 선택이다(ADR-0005 부록 기준 B). 효과 주장 없이
   사전등록 검증에 맡긴다.
5. **데이터 주입.** 펀딩·OI는 `attach_side_data()`로 러너가 주입하고, 모든 점수 계산에서
   *그 봉의 종료 시각까지 알려진 기록만* 쓴다(미래 기록이 바뀌어도 결과가 같다는 테스트 있음).
   `use_side_data=True`인데 그 시점에 펀딩 9회나 OI 6일이 없으면 패널 자체가 없어 거래하지 않는다
   (fail-closed).
6. **OI 로더** `BinanceVisionOpenInterestHistory`: daily metrics 아카이브의 하루 마지막 5분봉.
   누락일은 `ArchiveGap`으로 보고하고 채우지 않는다. 컬럼명은 아카이브 공개 스키마 기준이며
   이 샌드박스에서는 실제 파일로 확인하지 못했다(프록시 차단). 컬럼이 다르면 예외로 멈춘다.
7. 버전을 2로 올리고 ID에 `_side`를 넣어 가격 전용/부가데이터 후보를 구분한다. 보정 윈도우
   `fit_lookback`은 400에서 200으로 줄였다(일봉 워밍업 346봉으로 데이터 범위를 확보하려는 것).

## Consequences

- 후보 4개(가격 전용/부가데이터 x 보정 지평 5/10일)를 레지스트리에 등록했다. 시도 수는 늘어
  PBO/DSR이 더 엄격해진다.
- 데이터 확보 범위는 `scripts/check_data_coverage.py` 사전점검(등록·락 없음)으로 사실 확인한다.
- 성과 주장 없음. 검증은 ADR-0026.

## 사전등록 전 합성 데이터 스모크에서 찾은 버그 (2026-10-02)

검증 실행 전에 합성 일봉으로 `run_signal_study` 전체를 돌려(검증 아님, 파이프라인 점검) 아래 두 버그를
찾아 고쳤다. 고치지 않았다면 사전등록한 일회성 실행이 "거래 0회"로 끝났을 것이다.

1. ATR 윈도우가 1봉 모자라 모든 신호가 `atr_or_vol_unavailable`(거래 안 함)이었다.
2. 신호의 `regime`이 기본값 UNDEFINED라 리스크 엔진이 모든 진입을 `regime_undefined`로 거부했다.
   이제 `classify_regime` 결과를 신호에 싣는다(투표 아님, 정보용).

두 경우 모두 회귀 테스트를 추가했다. 교훈: 신호 단위 테스트만으로는 엔진·리스크 엔진과의 연결을
못 잡는다. 새 전략은 합성 데이터로 엔진 전체를 한 번 돌려 거래가 실제로 나는지 확인한 뒤 등록한다.
