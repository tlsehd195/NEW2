# ADR-0026: 지표 투표 후보 사전등록과 실데이터 검증

**Status:** Accepted (H-0022 실행 완료: 후보 4개 모두 REJECTED, TEST-22 잠금)
**Date:** 2026-10-02
**Deciders:** account owner (동동, "둘 다"로 사전등록·검증 승인), Claude Code session

## Context

ADR-0023/0025의 지표 투표 후보 4개(가격 전용/부가데이터 x 보정 지평 5·10일)를 CLAUDE.md의
검증 순서(사전등록 → locked window → 워크포워드 → PBO/DSR → TEST 1회)로 검증한다.
이 샌드박스는 Binance 아카이브에 접근할 수 없어서 검증은 GitHub Actions의
`signal_validation.yml`로만 돌린다.

## 사실 확인 (2026-10-02, `data_coverage.yml` 실행, 등록·락 없음)

BTCUSDT 일봉, 요청 2019-09-08~2022-08-17:

| 데이터 | 범위 | 빈 구간 |
|---|---|---|
| 캔들 | 2020-01-01 ~ 2022-08-16 (959개) | 없음 |
| 펀딩 | 2020-01-01 ~ 2022-08-16 (2877회) | 없음 |
| 미결제약정(OI) | 2020-09-01 ~ 2022-08-16 (715일) | 없음 |

OI 로더의 컬럼 가정(`create_time`, `sum_open_interest`)은 실제 파일로 맞았다.
2019-09~12의 캔들·펀딩·OI 누락은 아카이브에 파일이 없어서이고, 채우지 않았다.

## 선택지

- **BTCUSDT 일봉 2020-12-31~2022-08-17**: 이미 락된 구간(2022-08-17~2023-04-06,
  2024-06-18~) 때문에 쓸 수 있는 구간이 이것뿐이다. 워밍업 346봉을 빼면 워크포워드 폴드가
  14개로, 승격 기준 16개에 못 미친다. 최선의 결과가 INCONCLUSIVE다.
- **SOLUSDT 일봉 2021-09-15~2025-01-28**: 락이 없는 구간이고 약 30개 폴드. 승격 기준을
  판정할 수 있다. TEST(마지막 20%, 약 2024년 5월~2025년 1월)가 영구 락된다.

## Decision

동동님이 **SOLUSDT**를 선택했다(2026-10-02, "Sol"). 계획한 등록:

- 가설 id H-0022(다음 번호), SOLUSDT 일봉, `2022-01-15` ~ `2025-01-29`(끝 제외), 후보 4개, swing 정책
  (워크포워드 폴드 약 28개, TEST는 마지막 20%).
- 시작일 근거: 캔들 워밍업 352봉 때문에 2021-09 이후, 그리고 SOL의 OI 아카이브가 2021-12-01부터라
  부가데이터 후보가 처음부터 거래할 수 있게 2022-01-15로 잡았다. 끝은 SOL의 락(TEST-14, 2025-01-29~)
  직전이다.
- SOL 아카이브 사실(2026-10-02 Actions): 캔들 2020-09-14~, 펀딩 2020-09-13~, OI 2021-12-01~.
  캔들 빈 날이 2022-02-26과 2022-04-01 부근 2곳(최장 4일)이다. 엔진은 빈 봉을 건너뛰고 이어
  계산하므로, 이 구간의 지표와 손절 체결에는 빈 봉의 영향이 있다는 한계를 결과와 함께 적는다.

**막힌 점(해소됨, 아래 "실행 결과"):** 사전등록 코드(`research/hypotheses.py`)가 30일 안에 같은 계열(swing) 가설 3개
(H-0013, H-0015, H-0016)가 이미 있다며 등록을 거부한다(로컬에서 같은 함수로 재현 확인). 과적합을
막는 이 저장소의 규칙이라 코드나 후보 이름을 바꿔 우회하지 않았다. 예산이 풀리는 날은 H-0013 등록
후 30일인 2026-10-28이다. 사람이 예산을 올리는 예외를 승인하면 그 결정을 이 ADR에 추가하고 바로
실행한다.

## Consequences

- 어느 쪽이든 후보 4개 모두 한 가설 id로 사전등록하고, 시도 수는 DSR 보정에 들어간다.
- 결과는 `validation-status-guard`의 라벨(BACKTEST/INCONCLUSIVE 등)과 데이터 출처
  (`binance_vision_archive`)를 붙여 `PROJECT_STATUS.md`에 기록한다.

## 실행 결과 (2026-10-02, H-0022)

예산 상향은 동동님이 "상향"으로 직접 선택했고 ADR-0027에 기록했다. `signal_validation.yml`을 `main`에서
dispatch했다(run 37027517013). 라벨: **BACKTEST validation study (simulated; not paper or live
performance)**. 데이터 출처: `binance_vision_archive`(캔들, 펀딩, OI). 아래 숫자는 모두 시뮬레이션이다.

| 후보 | DSR | TEST 수익 | TEST 보유 수익 | TEST 거래 수 | 거래가 있었던 폴드 |
|---|---|---|---|---|---|
| vote h5 | 0.850 | +0.42% | +70.0% | 1 | 7/27 |
| vote h10 | 0.598 | -0.19% | +70.0% | 3 | 14/27 |
| vote+side h5 | 0.893 | +0.42% | +70.0% | 1 | 7/27 |
| vote+side h10 | 0.597 | -0.06% | +70.0% | 3 | 13/27 |

- 폴드 27개, PBO 0.9(기준 0.2 이하), DSR은 시도 71개로 보정. 원장 결과: 4개 모두 `REJECTED: pbo_above_max`.
  TEST-22(SOLUSDT, 2024-06-21~2025-01-29)를 잠갔다.
- 판정: **이 가설은 기준을 통과하지 못했다.** 엣지가 있다는 증거가 없다.
- 해석의 한계: 전략은 거의 거래하지 않았다(첫 20개 폴드에는 거래가 0건이고 TEST 구간 거래는 1~3건). 그래서
  TEST 초과수익은 사실상 "SOL 보유 수익(+70%)을 놓친 것"이고, PBO 0.9는 거의 같은 0 수익 후보들 사이의
  순위가 무의미한 데서 나온 값일 가능성이 크다. 이 결과만으로 지표 투표 아이디어 자체가 나쁘다고도, 좋다고도
  말할 수 없다. 진입 문턱(합산 확률 0.60 이상, 지표 60% 이상 동의)이 일봉 SOL에서 너무 엄격했을 수 있다.
- 부가데이터(변동성 게이트, 펀딩, OI)는 거래 수와 TEST 수익을 거의 바꾸지 못했다(h5는 TEST 거래가 동일).
- 데이터 한계: 캔들 빈 날 2022-02-26, 2022-04-01 부근; OI 아카이브 2021-12-01 이전 결번은 워밍업 구간이다.
  청산(liquidation)은 모델링되지 않았다(유지증거금 구간 없음).
- 후속: 같은 후보로 TEST를 다시 쓰지 않는다. 문턱을 바꾼 버전은 새 가설 id로 등록해야 하며, 30일 예산(3개)이
  다시 적용된다. 먼저 거래 빈도를 TEST 밖(학습/검증 구간)에서만 진단하는 것이 순서다.
