# ADR-0038: 세금 신고 자료 내보내기와 A안 레버리지 확정

**Status:** Accepted
**Date:** 2026-10-03
**Deciders:** account owner (동동), Claude Code session

## Context

동동님 결정(2026-10-03): 레버리지는 일단 **A안**으로 가고 B안 변경은 나중에 논의한다(ADR-0037). 또 해외
거래소에서 낸 수익을 세금 신고할 때 따로 정리하기 복잡하니 한 번에 처리하는 기능을 요청했다.

## Decision

1. **레버리지 A안 확정.** `configs/risk.json` 값(거래당 위험 0.5%, 상한 2배)은 그대로다. 안전장치를 진입 경로에
   연결했다: 모의 `PaperTrader`는 `configs/margin_policy.json`(격리 마진, 거래소 배율 3, 청산가가 손절 거리의
   3배 이상)으로 진입 직전에 검사하고, 어기거나 마진 등급표가 없으면 진입을 거절한다(`liquidation_too_close_to_stop`,
   `margin_tiers_unknown`). 실거래용 `LiveBroker.preflight`는 신규 진입 때 바이낸스 `symbolConfig`의 증거금 방식·
   배율이 정책과 다르면 거절한다. 청산(reduce-only) 주문은 설정 불일치로 막지 않는다.
2. **모의용 마진 등급표는 가정치다.** API 키 없이 실제 등급표를 받을 수 없어서 바이낸스 최저 구간보다 높은
   유지증거금률로 넣었고(검사가 더 엄격해지는 쪽), `verified=false`이며 모의 시작 때 경고를 띄운다. 실거래는 이
   파일이 아니라 거래소 응답을 써야 한다(ADR-0004). B안으로 바꿀 때는 `risk.json` 값 변경 + 새 사전등록 id가
   필요하다.
3. **세금 신고 자료는 연도별 3개 파일 묶음이다** (`accounting/tax_export.py`,
   `scripts/show_krw_pnl.py --export-year YYYY`): `summary`(항목별 원화 손익·공제·추정세액), `details`(숫자를
   만든 모든 건), `checklist`(미확정 사항과 기한). 합계와 세액은 보고서와 같은 숫자이고, 상세 합계가 요약 순손익과
   일치하는지 테스트한다. 엑셀에서 한글이 깨지지 않게 UTF-8 BOM으로 쓴다. 해당 연도에 기록이 없으면 빈 묶음을
   쓰지 않고 거절한다.
4. **확정되지 않은 것은 체크리스트에 질문으로 남긴다**: 해외 거래소 선물 손익의 소득 구분, 취득가 계산법(이동평균/
   선입선출), 의제취득가액, 시행 전 연도는 세액 0. 세무 조언이 아니며 `verified=false`인 동안 모든 세액에 "세무사 확인
   필요"를 붙인다.

## Consequences

- 해외금융계좌 신고(월말 잔고 5억원 초과)는 계산하지 않는다. 장부가 거래소별 잔고를 추적하지 않기 때문이며,
  체크리스트에 기한만 안내한다. 필요하면 이체 금액을 기록하도록 장부를 확장하는 별도 작업이다.
- 실거래 신고용으로 쓰려면 먼저 모드를 live로 장부를 만들어야 하고, 거래소 원본 내역과 대조해야 한다.
