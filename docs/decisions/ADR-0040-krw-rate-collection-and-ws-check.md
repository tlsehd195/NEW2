# ADR-0040: 원/USDT 환율 수집·모의투자 연결과 웹소켓 형식 확인 절차

**Status:** Accepted
**Date:** 2026-10-03
**Deciders:** account owner (동동), Claude Code session

## Context

원화 장부(ADR-0036)는 거래 시점의 원/USDT 환율이 필요한데 환율 수집기가 없어 CSV를 손으로 넣어야 했다. 또 모의투자
실행기에는 원화 순수익이 연결되어 있지 않았다. 바이낸스 웹소켓 파서는 문서 기준으로 만들었고 실제 메시지로 확인한 적이
없다(ADR-0015). 동동님이 남은 일을 처리하라고 했다(2026-10-03).

## Decision

1. **환율은 업비트 KRW-USDT 15분봉 종가**를 공개 REST(키 불필요)로 받아 `var/data/krw_usdt.csv`에 쌓는다
   (`accounting/krw_rates.py`, `scripts/collect_krw_rates.py`). 시각은 캔들의 **마감 시각**이라 아직 확정되지 않은
   값은 쓰이지 않는다. 다시 실행하면 새 것만 덧붙인다. 환율이 0, 500~5,000원 밖이거나 출처가 다르면 예외를 내고
   아무것도 쓰지 않는다. 구멍은 장부 쪽이 거부한다(`KrwRateSeries`가 1시간 넘게 오래된 환율은 안 씀).
2. **모의투자 실행기에 연결**: `scripts/run_paper_trader.py`가 15분마다 환율을 수집하는 백그라운드 스레드를 띄우고,
   첫 환율이 들어오면 모의 계좌 초기 USDT를 그 시점 환율·업비트 수수료 0.05%로 산 것으로 `var/paper/krw_flows.jsonl`에
   한 번 기록한다(환율이 변하면 환차손익으로 보인다). 수집 실패는 출력만 하고 거래를 멈추지 않는다. 종료할 때
   원화 기준 한 줄 요약을 출력하고, 자세한 건 `scripts/show_krw_pnl.py`(기본값이 모의투자 파일)로 본다.
   라이브/백테스트 모드는 `--flows`를 반드시 따로 주도록 막았다(실제 입출금 기록이 아니라 모의 파일로 계산하지 않게).
3. **웹소켓 형식 확인은 절차로 남긴다**: 개발 환경에서 바이낸스·업비트 접속이 막혀 있어(프록시 403) 실접속 확인을 할 수
   없다. `docs/runbooks/first-paper-run-ws-check.md`와 `scripts/check_ws_quality.py`(품질 이벤트 요약: malformed
   0건이고 결정이 나왔는지)로 첫 모의투자에서 확인한다. 확인 전 모의투자 결과는 신뢰하지 않는다.

## Consequences

- 테스트는 녹화한 업비트 응답 모양의 고정 응답으로 한다(수집 증분, 미마감 캔들 제외, 비정상 환율 거부, 네트워크 실패 시
  파일 미생성, 모의 시작 1회, 엔드투엔드 보고서). 이 환경에서 실제 업비트 호출은 403으로 막혀 실접속 검증은 못 했다.
- 사용자만 할 수 있는 것: 출금 수수료 금액 입력(`configs/krw_accounting.json`), 실제 접속 가능한 곳에서 모의투자 실행.
- 전략·리스크·사전등록·예산·레버리지 값은 바꾸지 않았다.
