# ADR-0041: 원화 평가손익 실시간 표시(업비트 현재가 REST 폴링)

**Status:** Accepted
**Date:** 2026-10-03
**Deciders:** account owner (동동), Claude Code session

## Context

동동님 질문(2026-10-03): 원화 순수익이 실시간으로 보이고 환율이 바뀌면 바로 반영되는가. 그때까지는 아니었다. 환율은 15분 캔들
종가를 15분마다 모았고(ADR-0040), 원화 요약은 종료할 때 한 줄만 나왔다.

## Decision

1. **환율은 업비트 KRW-USDT 현재가를 짧은 주기(기본 10초) REST로 받는다** (`accounting/krw_live.py`의 `UpbitTicker`).
   웹소켓 대신 REST를 고른 이유: 10초마다 GET 한 번은 업비트 호출 한도에 한참 못 미치고, 연결 관리·재연결 코드가 필요 없으며,
   한 번 실패해도 직전 값이 오래되면(마지막 체결이 5분을 넘으면) 쓰지 않는 방식이 가장 단순하고 안전하다. 응답이 한 개가 아니거나
   마켓이 다르거나 가격이 500~5,000원 밖이면 거부한다.
2. **평가 방식**: 모의 계좌의 현재 USDT 자산(지갑 + 미실현 손익, 브로커가 현재 호가로 계산)을 현재 환율로 바꿔, 실제로 낸 원화
   (시작 USDT 매수가 + 수수료)와 비교한다. 합계는 `매매(자산 − 시작USDT) × 현재환율 + 환차(시작USDT × (현재환율 − 매수환율)) −
   국내 수수료`로 정확히 나뉜다. 여기에 설정된 출금·매도 수수료(회수 비용)와 세금 추정을 더해 "지금 전부 회수하면" 세후 값도 보인다.
3. **표시**: `var/paper/krw_live.json`에 10초마다 원자적으로 쓰고(읽는 쪽이 반쯤 쓴 파일을 보지 않음), 모의투자 화면에 1분마다 한 줄을
   출력하며, `scripts/watch_krw_pnl.py`로 두 번째 터미널에서 계속 볼 수 있다(120초 넘게 갱신이 없으면 경고). 갱신이 실패하면 이전
   파일을 그대로 두고 `as_of`로 얼마나 오래된 값인지 드러내며, 같은 오류는 한 번만 출력한다.
4. **정확도 구분**: 이 값은 모든 손익을 지금 환율로 평가한 빠른 추정이다. 거래마다 그 시점 환율로 계산하는 장부
   (`show_krw_pnl.py`, ADR-0036)가 신고용 정확한 값이다. 세금은 같은 추정치이며 "세무사 확인 필요"가 붙는다.
5. **거래에는 영향이 없다**: 별도 스레드가 읽기만 하며 거래 결정, 15분봉 전략, 리스크, 레버리지 값은 바꾸지 않았다. 스레드가 브로커
   상태를 읽는 도중 값이 바뀌어 한 번 실패하면 다음 주기에 다시 시도한다.

## Consequences

- 테스트는 고정 응답으로 한다(신선/오래된/비정상/다른 마켓 환율, 환율이 내려가면 환차손익과 합계가 바로 내려가는지, 항목 합계, 회수·세금
  줄, 파일 원자 쓰기와 실패 시 이전 파일 유지, 모드 분리). **이 환경에서는 업비트 접속이 403으로 막혀 실제 현재가 호출은 검증하지
  못했다.** 첫 실제 모의투자에서 `krw_live.json`이 갱신되는지 확인해야 한다.
- 모의투자가 돌고 시작 USDT 매수 기록(첫 환율 수집 후)이 생겨야 값이 나온다. 그 전에는 "아직 없음" 메시지만 낸다.
- 라이브 모드의 실시간 평가는 실제 잔고 기록을 연결해야 하므로 이번 범위가 아니다.
