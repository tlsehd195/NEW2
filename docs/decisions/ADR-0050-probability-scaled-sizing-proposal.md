# ADR-0050: 확률에 따른 자금·레버리지 크기 공식 (제안)

**Status:** Accepted: C안을 나중에 도입 (2026-10-09 동동님 결정). 그때까지 A(고정 0.5%) 유지
**Date:** 2026-10-09
**Deciders:** account owner (동동), Claude Code session

## Context

동동님 요청(2026-10-08): 롱·숏 확률(투표 합성 확률)에 따라 자금과 레버리지를 얼마나 쓸지 정하는 공식이 있으면 좋겠다.

현재 크기 계산(`risk/engine.py` 244~257행, `configs/risk.json`, ADR-0037/0038 A안):

- 수량 = (자본 × 0.5%) ÷ 손절 거리. 손절에 걸리면 자본의 0.5%를 잃는다. 확률은 크기에 쓰이지 않는다
  (60%든 75%든 같은 크기). 확률은 진입 여부(≥ 60%, 6개 중 4개 동의)에만 쓰인다.
- 명목가 상한 = 자본 × 2배(`max_leverage`). 그래서 실효 레버리지 = 0.5% ÷ 손절 거리(%)이고, 손절 거리가
  0.25%보다 짧을 때만 2배 상한이 걸린다. 예: 손절 1% → 0.5배, 0.5% → 1배.
- 거래소 쪽은 격리 마진 3배 고정, 진입 전 청산가가 손절 거리의 3배 이상 떨어져 있어야 한다
  (`configs/margin_policy.json`). 3배 격리면 청산까지 약 1/3 − 유지증거금률 ≈ 32%라, 손절 거리가 약 10%
  이하면 통과한다. 이 규칙이 허용하는 거래소 배율 상한은 1 ÷ (3 × 손절 거리 + 유지증거금률)로, 손절 1%면
  약 25~28배다. 즉 지금 실제로 크기를 묶는 것은 청산 규칙이 아니라 0.5% 위험과 2배 상한이다.
- ADR-0042(BTC 15분봉 2023-04~2024-06): 투표가 60% 이상이라 한 구간의 실제 상승률은 49.0~51.4%,
  어느 후보도 "항상 기준 상승률로 예측"보다 Brier가 나았다. 숫자 60%는 실제 60%가 아니다.
- 위험·레버리지 값을 바꾸면 `RiskConfig.version()`이 바뀌고 새 사전등록이 필요하다. 등록 예산은
  2026-10-29 11:32 KST까지 차 있다.

## 켈리 비율로 계산해 보면

손절까지를 1R(자본의 f를 잃음), 이길 때 평균 b R을 번다고 하고, 왕복 비용을 c R(손절 1%, 비용 0.16% →
c ≈ 0.16)이라 하면 켈리가 말하는 "손절 시 잃어도 되는 자본 비율"은

    f* = [p(b − c) − (1 − p)(1 + c)] / [(b − c)(1 + c)]

이다(음수면 0, 즉 진입하지 않음). 손익비 b는 아직 측정한 적이 없다(목표가 없이 손절 2.5 ATR, 확률 하락,
12시간 시간 손절로 청산). b = 1, c = 0.16일 때:

| 확률 p | 50% | 51.4% (실측 최고) | 55% | 58% | 60% | 65% | 70% |
|---|---|---|---|---|---|---|---|
| 켈리 f* | 0 (−16%) | 0 (−14%) | 0 (−6%) | 0 | 4.1% | 14.4% | 24.6% |
| 1/4 켈리 | 0 | 0 | 0 | 0 | 1.0% | 3.6% | 6.2% |

- 비용을 넣으면 b = 1에서 손익분기 확률은 (1 + c) ÷ (b + 1) = **58%**다. 지금 실측 확률(49~51%)로는
  켈리가 **0, 즉 베팅하지 말라**고 한다. 비용이 없다고 쳐도 51.4%에서 2.8%가 최대다.
- 반대로 숫자 그대로(60%를 진짜 60%로) 믿으면 1/4 켈리만 해도 지금의 2배(1.0%)가 나온다. 보정 안 된
  확률로 켈리를 쓰면 크기를 키우는 쪽으로 틀린다.
- b = 1.5라면 결론이 달라진다(비용 포함 p = 50%에서 5.8%). 그래서 b를 먼저 재야 한다.

## 선택지

- **A. 지금처럼 고정 0.5% (현행)**: 확률은 진입 여부만 정한다. 확률이 보정되기 전에는 가장 안전하다.
- **B. 확률 구간별 단계**: 60~65% → 0.25%, 65~70% → 0.375%, 70% 이상 → 0.5%. 상한은 현행 0.5%라
  크기를 줄이기만 한다. 단, 구간이 높을수록 실제로 더 잘 맞는다는 측정이 없으면 근거 없는 단계다.
- **C. 보정 확률 × 1/4 켈리, 상한 0.5% (추천, 검증 후)**:

      위험 r = min(0.5%, ¼ × f*(p_보정, b_측정, c))
      명목 레버리지 = r ÷ 손절 거리, 상한 2배
      거래소 배율 ≤ 1 ÷ (3 × 손절 거리 + 유지증거금률), 그리고 3배 격리 고정 유지

  p_보정은 원래 투표 숫자가 아니라, 과거 데이터에서 "이 숫자일 때 실제로 몇 % 맞았나"로 바꾼 값이다.
  b는 페이퍼·백테스트 거래의 평균 이익 ÷ 평균 손실로 잰다. 상한이 현행 0.5%라 A보다 커지지 않고, 확률이
  손익분기 아래면 크기가 0이 되어 거래를 건너뛴다. 현재 실측값을 넣으면 거의 모든 신호가 0이 된다.
- **D. 켈리 상한 없이 (비추천)**: 보정이 조금만 틀려도 위험이 수 % 단위로 커진다. 하루 손실 한도 3%에
  한 번에 닿을 수 있다.

## Decision

2026-10-09 동동님이 C를 골랐다(나중에 도입). 지금은 A 유지, C는 다음 두 가지가 생긴 뒤 새 사전등록과 함께 도입:
(1) 투표 확률을 실제 적중률로 바꾸는 보정표(ADR-0042 방식, 검증 구간에서), (2) 측정한 손익비 b.

## Consequences

- 이번 변경은 문서뿐이다. `configs/risk.json`, `configs/margin_policy.json`, 매매·크기 코드는 그대로다.
- C를 고르면 할 일: 보정표 생성 도구, `RiskEngine`에 확률 입력과 위 공식 추가(상한·청산 규칙 유지),
  `risk.json`에 `sizing: {"mode": "kelly_fraction", "kelly_multiplier": 0.25, "max_risk": 0.005}` 같은
  항목. 값이 바뀌므로 새 사전등록 id가 필요하다(가장 이른 등록 2026-10-29 11:32 KST 이후).
- 코인끼리 상관이 높아(15분봉 0.80~0.87) 동시에 여러 코인에 켈리 크기를 걸면 실제 위험은 합쳐진다. C를
  도입하면 동시 보유 합산 위험 상한도 함께 정해야 한다.
