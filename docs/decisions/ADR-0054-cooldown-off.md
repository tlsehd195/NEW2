# ADR-0054: 쿨다운 해제와 리스크 한도 완화(모의투자 진입 빈도)

**Status:** Accepted
**Date:** 2026-10-09
**Deciders:** account owner, Claude Code session

## Context

모의투자 기록에 진입이 2번뿐이었다. 백테스트(ADR-0033, 0039)에서도 하루 약 1~1.3건이었고, 거래를 막는 건 투표가 아니라 리스크 엔진 보호(연패 가드, 쿨다운)였다. 쿨다운은 마지막 청산 후 30분(15분봉 2봉) 동안 신규 진입을 막는다. 사용자가 "일단 쿨다운 없애"를 지시했고, 이어서 "손절 3번은 너무 적다, 30번 나면 6시간 멈추게", "변동성 제한 좀 더 자유롭게, 일일 손실도 10퍼로"라고 지시했다.

## Decision

`configs/risk.json`의 `cooldown_minutes`를 30에서 0으로 바꾼다(0 = 끔, `settings.risk_from_dict`가 이미 지원). `stoploss_guard.max_losses`를 3에서 30으로 바꾼다(24시간 안에 순수익률이 음수인 청산 30번이면 6시간 중지, 기간·중지 시간은 그대로). 코드 변경 없음. 낙폭 가드(48시간 6%), 총 낙폭 15%, 스프레드 한도는 그대로.

`max_daily_loss`를 0.03에서 0.10으로, `max_atr_fraction`(리스크 엔진의 변동성 제한, 1시간봉 기준 ATR/가격)을 0.05에서 0.10으로 올린다. 사용자가 "변동성 저거 좀 더 자유롭게"라고만 해서 어느 변동성인지 정해지지 않았고, 기본값으로 이쪽을 골랐다. 15분봉 ATR은 보통 가격의 1% 미만이라 이 제한은 원래도 거의 걸리지 않는다. 전략의 변동성 게이트(`vol_gate_lo/hi` 0.5~2.0)는 건드리지 않았다.

## Consequences

- `risk.json`은 백테스트·선별·검증·모의가 함께 읽는다. `RiskConfig.version()`이 바뀌므로 이후 실행의 리스크 기록은 이전과 다른 버전이다. 이 변경 전 선별·진단 결과(쿨다운 30분)와 직접 비교하지 말 것.
- 연패 가드 30번은 15분봉 단타에서 사실상 거의 걸리지 않는 값이다(두 코인·두 전략으로 하루 수십 번 손실이 나야 함). 연속 손실 보호는 일일 손실 10%·낙폭 가드·총 낙폭 15%가 대신 맡는다. 일일 손실 10%는 하루에 자본의 10%까지 잃어야 멈추는 값이라 훨씬 느슨하다. 가드는 "손절"이 아니라 순수익률이 음수로 닫힌 모든 거래를 센다.
- 청산 직후 같은 신호로 바로 재진입할 수 있어 거래 수와 비용(왕복 약 0.12~0.20%)이 늘 수 있다. 백테스트에서 p>=60% 구간의 실제 상승률이 49~51%였으므로(ADR-0042) 수익이 늘 거라는 근거는 없다.
- 이 변경은 엣지 검증이 아니다. 실행 중인 모의투자는 재시작해야 반영된다.
