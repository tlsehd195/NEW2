# ADR-0059: 위험 B안(거래당 1%)과 레버리지 상한 20배

**Status:** Accepted
**Date:** 2026-10-10
**Deciders:** account owner (2026-10-10 대화), Claude Code session

## Context

ADR-0037/0038에서 사용자가 A안(거래당 위험 0.5%, 상한 2배)을 골랐고 B는 10-29 이후 논의로 미뤘다.
2026-10-10 사용자가 직접 B(거래당 1%)로 올리고 최대 레버리지를 20배로 하라고 정했다.

## Decision

- `configs/risk.json`: `risk_per_trade` 0.005 → 0.01, `max_leverage` 2.0 → 20.0.
- `configs/margin_policy.json`: `exchange_leverage` 3 → 20. 격리 마진은 명목금액 / 거래소 레버리지로 채워지므로
  거래소 설정은 어떤 포지션의 레버리지보다 작을 수 없다(테스트로 고정).
- 대시보드: `effective_leverage`(= 명목금액 / 계좌 잔고) 추가. 기존 `leverage`/`margin`은 거래소 설정 기준 증거금 추정.
- 가설 사전등록·예산은 쓰지 않았다(코드가 risk.json을 사전등록과 연결하지 않으며, `RiskConfig.version()`만 바뀐다).
  단, 이 값으로 새 사전등록을 하는 것은 예산이 풀리는 10-29 이후다.

## 포지션 크기·레버리지 공식 (`risk/engine.py`)

1. 위험금액 = 자본 × `risk_per_trade`
2. 수량 = 위험금액 / 손절거리 (손절거리 = `stop_atr` × ATR(14), 가격 단위)
3. 상한: 명목금액 ≤ 자본 × `max_leverage` − 이미 열린 포지션 명목금액
4. 포지션 레버리지 = 명목금액 / 자본 = `risk_per_trade` / (손절거리 / 가격)

손절 1%면 1배, 0.5%면 2배, 0.1%면 10배. 레버리지는 고르는 값이 아니라 손절이 좁을수록 자동으로 커지는 결과이고,
20배는 손절이 가격의 0.05%(1% ÷ 20) 이하일 때만 걸리는 천장이다. 손절을 맞으면 손실은 항상 자본의 약 1%(+수수료·슬리피지).

## 청산가 확인 (20배)

진입 전 청산가가 손절거리의 3배 이상 떨어져야 한다. 마진을 거래소 설정(20배) 기준 명목금액/20으로 계산하므로
실제 포지션 레버리지가 낮아도 보수적으로 막는다. 가정 등급표(verified=false)로 계산한 결과(명목금액 < 50,000 구간):

| 진입가 대비 손절 | BTC 롱 | BTC 숏 | ETH 롱/숏 |
|---|---|---|---|
| 0.3~1.2% | 통과 | 통과 | 통과 |
| 1.5% | 통과 | 차단 | 차단 |
| 2.0% 이상 | 차단 | 차단 | 차단 |

이전(3배)에는 사실상 막힌 적이 없었다. 20배에서는 손절이 약 1.4% 넘는 진입이 막힌다. 실제 15분봉 손절 폭
분포로 얼마나 자주 막히는지는 측정하지 못했다(첫 모의투자 기록 필요).

## Consequences

- 이전 모의투자 성과(0.5%/2배)와 비교할 수 없다. 모의투자는 새 설정으로 다시 시작해야 한다(RiskConfig 버전이 바뀜).
- 거래당 손실 한도가 2배라 같은 승률에서 변동·낙폭이 2배다. `max_daily_loss` 10%, `max_drawdown` 15%, 낙폭 보호(6%/48h)는 그대로라
  더 빨리 닿는다.
- 라이브에서는 Binance 심볼별 레버리지를 20으로 맞춰야 하며(`margin_settings_mismatches`), 실제 등급표로 청산가 확인을 다시 해야 한다.
- 확률 기반 크기 조절(ADR-0050 C안)은 별개이며 여전히 보류.
